# NOESIS E05 — Προσαρμοζόμενη μνήμη με συνέχεια μεταξύ εκτελέσεων

Το E05 προσθέτει επαναχρησιμοποιήσιμο πειραματικό πυρήνα. Κρατά τέσσερις
εκδοχές της εμπειρίας, μεταβάλλει τα βάρη τους από τις προβλέψεις τους και
αποθηκεύει τη μνήμη σε JSON. Δεν απαιτεί GPU, API key ή εξωτερικό AI.
Απαιτεί Python 3.10+ και μόνο τη standard library.

## Τι κάνει

- `archive`: διατηρεί το αρχικό curriculum αμετάβλητο.
- `long`: συσσωρεύει όλες τις επόμενες επιλυμένες εργασίες.
- `recent`: μειώνει τις προηγούμενες συχνότητες με συντελεστή 0,9 ανά εργασία.
- `fast`: μειώνει τις προηγούμενες συχνότητες με συντελεστή 0,5.

Ο controller προσαρμόζει πόσο βάρος δίνει σε κάθε μνήμη. Δεν μαθαίνει τους
παραπάνω συντελεστές, ούτε ανακαλύπτει νέους τύπους μνήμης. Το archive δεν
είναι βιβλιοθήκη ξεχωριστών επεισοδίων ή αυτόματη αναγνώριση παλιού πλαισίου.

Η ενημέρωση βασίζεται στην πιθανότητα που έδινε κάθε μνήμη στη λύση **πριν**
ξεκινήσει το πρόβλημα. Η λύση εισέρχεται στη μνήμη μόνο όταν έχει εξαχθεί από
τις πραγματικές παρατηρήσεις και απομένει μία υπόθεση. Δεν δίνεται στον agent
ο κρυφός στόχος, η ταυτότητα του περιβάλλοντος ή η στιγμή αλλαγής του.

## Demo και αποθήκευση

Από `experiments/e05`:

```bash
python3 -m noesis --demo --tasks 20 --state-out my_memory.json
python3 -m noesis --demo --tasks 20 --state-in my_memory.json --state-out my_memory.json
```

Η δεύτερη εντολή συνεχίζει από την εργασία 21, χωρίς νέο curriculum. Το demo
τυπώνει τις ερωτήσεις και τα βάρη των τεσσάρων μνημών. Η στήλη
`evaluator_regime` δίνεται μόνο στον άνθρωπο από τον evaluator, όχι στον agent.
Το demo είναι επίδειξη, όχι η αξιολόγηση με διαχωρισμένα δεδομένα.

Η αποθήκευση επιτρέπεται ανάμεσα σε ολοκληρωμένες εργασίες. Η εγγραφή είναι
ατομική, με έλεγχο ακεραιότητας και συμβατότητας της γραμματικής. Χρησιμοποιεί
JSON, όχι εκτέλεση σειριοποιημένου κώδικα. Το checksum ανιχνεύει αλλοίωση αλλά
δεν είναι ψηφιακή υπογραφή ούτε κρυπτογράφηση. Το `--state-out` αντικαθιστά το
συγκεκριμένο checkpoint ώστε να ενημερώνεται η μνήμη.

## Έλεγχοι και πλήρες πείραμα

```bash
python3 -m unittest discover -s tests -v
python3 verify_results.py results_01
python3 -m noesis --config config.json --out mac_e05_results_01
python3 verify_results.py mac_e05_results_01
```

Ο φάκελος εξόδου της πλήρους εκτέλεσης πρέπει να είναι καινούργιος. Η εκτέλεση
περιλαμβάνει 50 seeds × 4 streams × 80 εργασίες × 6 πολιτικές = 96.000
εκτελέσεις agents πάνω σε 16.000 κοινές εργασίες. Μπορεί να χρειαστεί αρκετά
λεπτά, ιδίως μαζί με τον ανεξάρτητο έλεγχο των bootstrap διαστημάτων.

Δες το [πρωτόκολλο](PROTOCOL.md) και την [αναφορά](results_01/REPORT_GR.md).

**Αποτέλεσμα:** το συνολικό gate απέτυχε. Η προσαρμογή κέρδισε τη σταθερή
ανάμειξη, αλλά δεν τεκμηριώθηκε υπεροχή έναντι του απλού recency=0,9.
Το demo δείχνει τον experimental adaptive controller· δεν αποτελεί σύσταση
ότι αυτός είναι πάντα προτιμότερος. Το API επιτρέπει `method='recency'` ή
`method='cumulative'` για τις απλές συγκρίσεις.
Τα checkpoints της αξιολόγησης σώζονται ανά seed και stream στον φάκελο
`results_01/checkpoints/`. Φορτώνονται από το ίδιο API, αλλά δεν πρέπει να
χρησιμοποιηθούν ως εκπαίδευση σε αξιολόγηση που υποτίθεται ότι παραμένει αθέατη.

## Χρήση του πυρήνα από δικό μας περιβάλλον

```python
from noesis import MemoryEngine
from noesis.core import grammar

engine = MemoryEngine(grammar(2))
engine.start_task(seed=123)
while not engine.identified:
    x = engine.select()
    y = your_environment.query(x)  # πραγματική παρατήρηση 0 ή 1
    engine.observe(x, y)
result = engine.finish_task()
engine.save('memory.json')
restored = MemoryEngine.load(grammar(2), 'memory.json')
```

Το API εξακολουθεί να αφορά τη συγκεκριμένη πεπερασμένη περιοχή Boolean
προβλημάτων. Αν οι παρατηρήσεις είναι ασύμβατες με τη γραμματική, αποτυγχάνει
ρητά. Δεν χειρίζεται ακόμη θόρυβο, φυσική γλώσσα ή αυθαίρετα προβλήματα.

## Ερευνητική βάση

Το fixed-share των Herbster και Warmuth (1998) ενημερώνει βάρη προβλεπτών από
την απώλειά τους και αναδιανέμει μέρος του βάρους, ώστε ένας παραμελημένος
προβλεπτής να μπορεί να ανακάμψει. Χρησιμοποιούμε αυτή την οικογένεια κανόνων
με λογαριθμική απώλεια ανά επιλυμένο πρόβλημα. Δεν ισχυριζόμαστε ότι τα
θεωρητικά αποτελέσματα του paper εγγυώνται λιγότερες ερωτήσεις στο NOESIS.

Πρωτογενής πηγή: [Herbster & Warmuth, Tracking the Best Expert, Machine Learning 32, 151–178](https://mwarmuth.bitbucket.io/pubs/J39.pdf).
Η υλοποίηση και η εφαρμογή σε αυτά τα προβλήματα αξιολογούνται χωριστά από
τους ισχυρισμούς του paper. Δεν έχει γίνει αντιγραφή ανθρώπινης νόησης.

Η αποθηκευμένη εκτέλεση του repo χωρίζεται σε δύο συμπιεσμένα αρχεία τροχιών
για το όριο μεταφοράς. Οι γραμμές είναι ακριβώς οι ίδιες με την ενιαία καταγραφή.
Ο ελεγκτής δέχεται είτε την ενιαία έξοδο νέας εκτέλεσης είτε αυτά τα δύο μέρη.
